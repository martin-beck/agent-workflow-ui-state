# AR-0071: Remote self-bootstrapping UI handoff

Make the human decision handoff usable when the controlling machine does not
already have `awui-connect` on `PATH`. A short shell command fetched from the
authoritative SSH host must negotiate the local platform, architecture,
distribution/runtime, shell, and GUI capability; select a trusted launcher
matching those facts; prefer the GUI and fall back to the TUI; preserve the
user's SSH config alias; and clean temporary files after the revision-bound
event journal is copied back.

Acceptance:

- Windows PowerShell and POSIX bootstrap scripts are version-pinned and
  fetched from a validated absolute path on the authoritative host;
- negotiation records platform, architecture, runtime/Python, distribution,
  shell, display, and GUI capability without trusting remote claims;
- GUI is selected whenever locally usable, with an explicit TUI fallback;
- request/result paths remain remote-authoritative and are validated against
  traversal/control-character injection;
- scripts use bounded temporary state, fail closed on missing runtimes or
  failed installation, and remove their launcher files;
- unit, hostile-input, local shim, and hosted Linux/Windows CI tests pass.
