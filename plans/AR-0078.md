# AR-0078: Coordinator-issued dynamic decision tokens

Define and implement the authoritative runtime path by which the Coordinator
creates a short token for one complete, batched human-decision session. The
token must be generated at decision time, bound to the exact project, AR
revision, batch/session identity, packet digest, SSH alias, request path, and
event destination, and exposed to the autonomous worker as a copyable user
command. The token registry remains private Coordinator state and never
contains plaintext tokens, credentials, prompts, or unbounded transcript data.

Acceptance:

- Coordinator creates a token only for a non-empty, revision-valid complete
  batch and records an auditable issue event and expiry policy;
- token values are cryptographically random, short, collision-checked, and
  returned exactly once to the worker/user handoff surface;
- registry records contain only a digest and validated routing metadata;
- issuing a token for a second independent decision in the same pending batch
  is rejected, ensuring one UI session covers the whole batch;
- issuance rejects stale AR revisions, missing event destinations, unsafe
  paths/aliases, duplicate active sessions, and malformed packet digests;
- Coordinator, bridge, UI, and umbrella compatibility schemas are updated
  with fixtures and focused tests.
