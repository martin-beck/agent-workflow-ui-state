# AR-0107: Android decision client parity

1. Build the development Android application with the same batch, proposal,
   Markdown/design/workplan, highlight, navigation, audit, save, and conflict
   interactions as the Qt GUI and TUI.
2. Make phone confirmation and event acknowledgement visibly explicit.

Acceptance evidence:

- Android UI tests cover every decision action and the same hostile guards as
  the existing renderers.
- A decision selected on Android produces the same canonical event/snapshot as
  the GUI and TUI.
