# AR-0081: Real-environment dynamic-token qualification

Provide reproducible end-to-end qualification for the entire dynamic-token
workflow. The test matrix must exercise a Coordinator-issued token, a remote
authoritative state host, and a separate controlling user machine rather than
only mocked registry reads or local connector callbacks.

Acceptance:

- CI or bounded disposable runners cover Linux-to-Linux, Windows-to-Linux,
  Linux-to-Windows-compatible, x86_64, and at least one non-x86 fixture;
- each run issues one multi-decision token, launches GUI/TUI, persists all
  final events remotely, verifies AR revision binding, and rejects replay;
- SSH config aliases, ProxyJump/identity selection, display absence, GUI
  fallback, network interruption, retry, expiry, and concurrent launch are
  covered;
- artifacts contain only sanitized request/event metadata and test evidence;
  no credentials, private paths, prompts, or raw transcripts are published;
- hosted CI, local deterministic tests, release qualification, and real-device
  limitations are reported separately with exact commit evidence.
