# AR-0082: Dynamic-token operator documentation and compatibility release

Document the supported real-world workflow and publish a synchronized release
only after the dynamic issuance, remote completion, installation, and
qualification ARs pass. Documentation must make clear what the autonomous
worker prints, what the user runs locally, where the authoritative event
journal is written, and how retry/replay/expiry behave.

Acceptance:

- Windows PowerShell and POSIX examples use the current immutable release and
  show installation/configuration plus the short token command;
- examples distinguish a real Coordinator-issued token from placeholder
  tokens and include GUI-first/TUI fallback behavior;
- Coordinator, UI, Guidance, Quality, and umbrella compatibility manifests
  pin mutually compatible releases and bridge schema versions;
- generated docs and scenario artifacts are refreshed from the current source
  AR graph, with privacy checks and no stale release URLs;
- a tagged UI release and umbrella compatibility update are made only with
  exact-head, hosted-CI, end-to-end evidence and a truthful limitations note.
