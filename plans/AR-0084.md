# AR-0084: Authoritative dynamic-token issuance and publication

Dynamic tokens are only useful when the SSH authority can resolve them. The
Coordinator must create the complete batch request, registry record, and
revision-bound token on the authoritative host before emitting the user
command.

Acceptance:

- One transaction publishes the complete deduplicated batch request and token
  registry with private permissions.
- The issued token is bound to project, session, AR revision, packet digest,
  SSH alias, event path, and expiry; registry files contain only digests.
- A failed publication produces no user command and no misleading local token.
- Retry after transport failure is safe; successful completion consumes exactly
  one token, while cancellation leaves it retryable until expiry.
- Tests cover stale revision, wrong host, replay, expiry, partial upload, and
  authority restart.
