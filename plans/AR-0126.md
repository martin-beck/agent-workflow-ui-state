# AR-0126 plan: SSH-rendezvous HTTPS bootstrap

Make the first phone registration reachable when the workflow host is behind
NAT. When pairing starts the service with a configured SSH rendezvous, forward
the actual HTTPS listener through the rendezvous server, derive the allocated
`https://host:port` endpoint, and place that endpoint in the QR. Preserve
one-time registration, TLS validation, and post-registration authenticated
SSH behavior. Document the required GatewayPorts and certificate conditions.

Verification: focused pairing/server/service tests, Android protocol tests,
release qualification, and umbrella compatibility pin update.
