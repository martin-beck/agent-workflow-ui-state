# AR-0119: Public endpoint and relay candidate discovery

Add a candidate-discovery layer after SSH enumeration. Candidates may come
from configured DNS, VPN overlays, optional remote IP reflection, STUN, or an
explicit relay. Include expiry, provenance, address family, and expected host
key. The phone performs the authoritative reachability test; service-side
reachability alone is insufficient.

Acceptance requires deterministic no-network fixtures plus opt-in integration
tests for public-IP reflection, relay fallback, and inaccessible candidates.
