# AR-0080: Remote-machine installation and environment prerequisites

Make the dynamic-token command usable in real user environments. The
one-time installer and fallback bootstrap must configure the authoritative SSH
alias and remote state root, detect Windows/Linux/macOS, architecture, Python,
display capability, and GUI/TUI availability, and install or fetch the exact
compatible UI release without administrator rights. Configuration must remain
non-secret and use the user's existing SSH agent/configuration.

Acceptance:

- fresh Windows PowerShell and Linux/macOS shells can install or bootstrap
  the pinned release and run `awui [HOST] TOKEN` without PATH surprises;
- missing or invalid host/root configuration produces an actionable error
  before any token is consumed;
- GUI is selected when a usable local display and PySide6 runtime exist;
  otherwise the complete TUI is selected with identical bridge semantics;
- architecture, distribution/libc, runtime, shell, display, and SSH capability
  negotiation are recorded as bounded diagnostics and mismatches fail closed;
- temporary runtimes, requests, registries, and journals are cleaned up while
  authoritative event files remain on the remote host;
- installer hashes, release pins, permissions, proxy/jump-host aliases, and
  interrupted-install recovery are tested on Windows and POSIX fixtures.
