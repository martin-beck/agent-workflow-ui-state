# AR-0127 plan: Android authoritative batch content parity

Make the Android decision workspace a faithful client of the revision-bound
batch published by the workflow service. The app must render the supplied
`design_markdown` and `workplan_markdown`, select the document-specific
highlight for the active decision, and expose proposal detail metadata without
inventing fallback documents or decisions. Proposal rationale, implications,
trade-offs, confidence, reversibility, evidence references, and helper text
remain available while deciding and are included in accessibility semantics.

The implementation must preserve the batch/session/packet binding and current
event protocol. Empty or malformed authoritative batches are displayed as an
empty/error state, never replaced with fabricated decisions. Document changes
must retain the selected decision and scroll the active anchor into view.

Verification: Kotlin unit/UI tests for parsing, real Markdown documents,
document-specific highlights, proposal metadata and empty batches; Android
compile/test; Python bridge validation; PR and hosted checks.
