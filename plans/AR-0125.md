# AR-0125 plan: HTTPS service startup during Android pairing

Implement a pairing entry point that verifies the configured HTTPS service,
starts it when absent using operator-provided TLS credentials, waits for its
health endpoint, and then creates the one-time QR. Reuse an existing healthy
listener and preserve configurable SSH rendezvous options.

Verification: focused offline startup/reuse/health tests, hosted Android ABI
builds, Windows qualification, scenario replay, and release qualification.
